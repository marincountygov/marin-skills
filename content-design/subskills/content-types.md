# Content types

Classify content by function so it gets the right structure, lifecycle, and metadata. See `marin-digital-standards/content-design/content-patterns.md` for the canonical definition of each content type — this workflow is how to apply that classification to a specific item.

## Core rule

Choose the content type based on what the user needs to do, not what the organization wants to publish.

## Selection questions

What user action or decision does this support? Is this content evergreen, seasonal, urgent, scheduled, or archival? Is this the source of truth or a pointer to it? Does it need a review date, expiration date, or event date? Does it need structured metadata or taxonomy? Would a page serve better than a downloadable document? Should this be merged with existing content?

## Success measures by type

Roughly aligned to the content types in `marin-digital-standards/content-design/content-patterns.md`:

- **Service page**: completed applications/payments/registrations, reduced support contacts, lower abandonment, fewer duplicate/misdirected requests.
- **Guide or explainer**: reduced confusion, improved progression to the correct next step, lower support burden.
- **Policy or requirement**: users can identify the current applicable requirement, reduced use of outdated versions.
- **News or announcement**: reach during the relevant window, click-through to the permanent source, reduced confusion during transition.
- **Alert or urgent notice**: timely visibility, reduced calls or misdirected visits, clear user action during disruption.
- **Event**: registrations/attendance, agenda/document access, post-event follow-up completion.
- **Campaign or landing page**: campaign conversions, click-through to key actions, reach within target audience.
- **Form, document, or downloadable asset**: correct-version downloads, reduced outdated-file use, fewer incomplete/incorrect submissions.
- **Directory or index**: search refinement success, click-through to the correct item, reduced failed searches.
