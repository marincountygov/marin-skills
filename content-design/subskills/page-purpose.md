# Page purpose

Define why a specific page or content asset exists. See `marin-digital-standards/content-design/principles.md` and `content-patterns.md` for the purpose-statement format and the page-purpose types this workflow applies.

## Core rule

A page has one primary purpose. If it has several unrelated purposes, recommend splitting, restructuring, or creating clearer pathways between separate pages.

## Purpose statement

> This page exists to help [audience] [complete a task or answer a question] so they can [user outcome], while supporting [organizational purpose].

Example: "This page exists to help property owners understand whether they need a permit and start the correct application so they can avoid delays, while supporting accurate permit intake."

## Good vs. weak purposes

Strong purposes are specific, user-centered, actionable, measurable, owned, and distinct from nearby pages. Revise anything that only says "provide information," "promote awareness," "tell people about our program," or "explain what we do" — those are starting points, not strategy.

## Review questions

What user problem does this page solve? What would users fail to do if it didn't exist? What's the one most important thing users should be able to do after using it? Is the page the source of truth or a route to one? Does this overlap with another page? What happens to the page when its purpose expires?

## Decision rules

If no user task or question can be stated, don't recommend publishing the page as proposed. If the page exists mainly for internal visibility, consider whether it belongs on an internal channel instead. If it duplicates another page, recommend merge, redirect, or clarify the distinct purposes. If it's time-limited, define a sunset or archive trigger up front.
