# Placement and metadata

Decide where content belongs and how it should be described and tagged. See `marin-digital-standards/content-design/content-patterns.md` for the underlying taxonomy design principles (user-centered labels, avoid over-tagging, separate departments from topics) — this workflow applies them to a specific item.

## Metadata vs. taxonomy

**Metadata** is structured information about one content item: title, summary, content type, audience, owner, department/service area, topic, location, publish/review/expiration date, status, language, related service.

**Taxonomy** is the controlled categories and relationships used to organize and retrieve content across items: topic categories, service categories, audience groups, locations, departments, content types, lifecycle states, campaign tags.

## Required metadata fields

For strategic governance, most content needs: title, description/summary, content type, primary audience, user intent, owner, source of truth, topic/service category, lifecycle state, publish date, last-reviewed date, next-review date, expiration/sunset date if applicable.

Optional, when relevant: geographic location, eligibility group, related department/form/fee/deadline, event date, campaign/program name, policy authority, document version, language, redirect target, archive reason.

## Information architecture placement

Evaluate: primary user task, content type, topic/service area, audience, source of truth, related pages, navigation path, search behavior, ownership.

## Common taxonomy facets

Use as candidates, not defaults — a facet only earns its place if it changes findability or governance for real content:

| Facet | Use when |
|---|---|
| Topic | Users browse by subject |
| Service | Users need to complete a transaction |
| Audience | Requirements differ by user group |
| Location | Content varies by place or facility |
| Department | Ownership or accountability matters |
| Content type | Users filter by format or function |
| Date | Timeliness matters |
| Lifecycle status | Governance or maintenance matters |
| Campaign | Content belongs to a temporary initiative |

## Metadata quality checks

Good metadata is accurate, specific, consistent, controlled where needed, useful to both users and maintainers, and maintained alongside the content. Weak metadata: vague titles, duplicative categories, internal acronyms, empty owner fields, missing review dates, tags that don't change findability or governance for anyone.

## Decision rules

If users search by task, tag by service or action rather than department alone. If content is time-limited, require expiration/review metadata. If content is authoritative, require owner, source, effective date, and version where applicable. If content is duplicated, metadata alone isn't enough — recommend merge, redirect, or a clarified purpose. If a taxonomy term is used once with no governance value, question whether it's needed at all.
