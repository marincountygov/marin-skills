# Digital Service Design Skill

> **Canonical requirements have moved.** The five-question service model, operating principles, default page structure, journey stages, task-flow rules, and failure-state/status-message patterns are now canonical in [marin-digital-standards/product-design](https://github.com/marincountygov/marin-digital-standards/tree/main/product-design). This skill is the workflow that applies them to a specific service — the required review dimensions, subskill routing, and output formats below.

## Purpose

Improve resident task completion for County services such as applying, paying, reporting, requesting, registering, appealing, contacting, or checking eligibility.

Use this skill to make digital services easier to understand, complete, recover from, and follow up on. The skill focuses on the full resident task, not only the web page, form, or message currently being edited.

## When to use this skill

Use this skill when working on content or workflows for a resident-facing service, especially when the user is trying to:

- Apply for a program, permit, benefit, license, job, appointment, or service.
- Pay a bill, fee, fine, tax, permit charge, registration fee, or other County obligation.
- Report a problem, concern, violation, hazard, incident, outage, or change in circumstances.
- Request records, assistance, maintenance, inspections, information, accommodations, or appointments.
- Register for events, programs, alerts, classes, accounts, permits, or recurring services.
- Appeal, dispute, respond to, renew, cancel, reschedule, update, or check status.
- Determine eligibility, required documents, deadlines, fees, processing times, or next steps.

See `marin-digital-standards/product-design/principles.md` for the five-question model and operating principles this skill applies.

## Required service-design review

For any service page, workflow, form, transaction, or notice, review these dimensions:

1. **Service journey** — Where does the task begin and end from the resident’s perspective?
2. **Task flow** — What must the resident do, in what order, and through which channels?
3. **Forms and transactions** — What information, documents, signatures, payments, or confirmations are required?
4. **Eligibility and requirements** — Who can use the service, what disqualifies them, and what must they prepare?
5. **Status, confirmation, and next steps** — How does the resident know the County received the request, what happens next, and when?
6. **Failure states** — What happens when the resident is ineligible, submits incomplete information, misses a deadline, cannot pay, encounters an error, or needs help?

## Subskills

Use these subskills as needed:

- `subskills/service-journeys.md` — map the end-to-end resident journey across channels and handoffs.
- `subskills/task-flows.md` — convert services into clear step-by-step flows.
- `subskills/forms-and-transactions.md` — improve forms, applications, payments, uploads, signatures, and submissions.
- `subskills/eligibility-and-requirements.md` — clarify who can use the service and what is required before starting.
- `subskills/status-confirmation-next-steps.md` — design receipts, confirmations, status messages, next steps, and follow-up instructions.
- `subskills/failure-states.md` — handle errors, dead ends, rejection, ineligibility, missed deadlines, and recovery paths.

## Output formats

Use the format that best matches the user’s request:

- Service journey map
- Task-flow outline
- Page purpose statement
- Service page rewrite
- Form improvement notes
- Eligibility and requirement checklist
- Confirmation or receipt message
- Status-message pattern
- Failure-state recovery table
- Service-quality review checklist

See `marin-digital-standards/product-design/principles.md` for the default service page structure and quality checklist this skill applies when drafting or reviewing a service page.

## Boundaries

This skill does not replace separate skills for accessibility, plain language, visual identity, legal review, privacy, security, or technical implementation. When those concerns arise, route to the appropriate specialized skill while preserving the service-design intent.
